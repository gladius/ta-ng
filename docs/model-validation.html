Finding the call-sites

Everything after this works per call-site. The log has no call-site id, so we can't pull a call-site's calls by id. We have to find them first.

What is a call-site?

One place in a program's code that calls the model. Every call from there uses the same prompt template and does the same job; only the data changes. It is the smallest unit where "can a cheaper model do this?" has one answer.

How a model is validated

The same steps for every model and every reason: a cheaper model, a better-value one, a new release.

CALL-SITE 1 template

One prompt template, found by its phrases (section 1). Everything below is measured on it alone.

SAMPLE 12

Logged requests, picked by size and speed (section 3).

ORIGINAL 1 + 4

The logged answer plus 4 fresh re-runs of the same request, sent exactly as logged. That is the original's own range.

CANDIDATE 3 → 5

3 answers per request. 2 more only when one of the 3 isn't a pass.

JUDGE reads all

The whole request and every answer. Never cut. Each candidate answer gets a verdict.

FINDING pass / fail

Per call-site and model, with cost and latency from the same calls. Valid 30 days, or until the prompt changes.

Why we sample this way

A model rarely fails on the typical request. It fails at the edges: the tiny input, the huge one, the long answer, the slow tool loop. 12 picks cover the edges first, then the middle.

Empty fields, a missing document, one-line input. Cheap models tend to invent what isn't there.

Drift shows on different requests far more than on repeats of one. So 3 answers first, and 5 only where a doubt appears.

4

Challenges

What makes this hard, and where each one stands.

The log never says which program sent a call

handled

The gateway log has the team (usecase), the model and the text. No program id, no session id, nothing in the headers.

What we do: find each call-site once by the text it repeats; its proven phrases then place its calls every day (section 1).

One wrapper, many agents

open

A shared agent framework opens every call with the same long text. Its agents differ only after it. One usecase: 451 different tool lists, about 27 calls each, read as one call-site.

Next: a second level under the call-site, split by tool list or the text after the shared opening, each split proven by count.

Values inside the template

handled

Names, dates, ids written into the instructions make one template look like thousands.

What we do: only text that repeats across many calls defines a call-site; one-off values never do.

The original disagrees with itself

handled

Asked twice, the same model gives different answers. An exact-match test would fail every model, the original too.

What we do: 4 re-runs give the original's own range; the candidate is held to that. Below 60% self-agreement: not certified.

Requests too large for the judge

handled

A cut request would hide exactly the part that broke.

What we do: never cut. Too large means "not verified", shown as such.

Agents run in many steps

known limit

A run is a chain of calls with tool results in between. We can't run the tools again.

What we do: each call is replayed alone with its logged history. A different tool call or argument counts as a changed action: drift.

Prompts change

handled

A team edits its template; last month's verdict says nothing about the new one.

What we do: a finding holds for the prompt version it was measured on, and for 30 days at most.

The gateway is shared production

handled

Our re-runs must not hit a cache, land in the log, or be counted as a team's traffic.

What we do: every re-run and judge call goes out with no-cache and no-log.

It costs money

handled

Per request: 4 original re-runs, up to 5 per candidate, plus judge votes. Reading a day of the log bills the whole day.

What we do: a cost estimate before each audit and a hard budget on its job; a read over 2 TB is refused before it runs.

The guard

A pin holds for the part of the traffic the validation covered: e.g. prompts under the largest one sampled. Outside it, the requested model.

Pins expire

When the call-site's prompt changes, when the model behind a name changes, and after 30 days. The next audit earns it again.

A new release

Re-audited on every pinned call-site before it takes traffic. If it drifts, the pin stays on the old model.

Never downgraded

A deny-list outranks any finding: regulated decisions, safety checks, legal text a customer sees.

The engine's settings: 12 samples, 4 re-runs, 3 then 5 candidate answers, 3 judge votes, 60% floor, 20-point margin, judge claude-sonnet-5, findings valid 30 days. Distributions and call-site names are examples.
